    Quick start
    
    
      
     
    • 1. Pick a start. In the Editor choose a game preset (All loot, Tidy, Strict, Very strict, End Game). It is only a starting point; change anything.
      • 
     
    • 2. Edit the rules. Select a rule in the list and set what it checks and what it does. Add, duplicate or remove rules, and move them up or down.
      • 
     
    • 3. Test it. Open Drop Test and press Drop 25 or a Quick spawn button. Every sample item shows the rule that caught it.
      • 
     
    • 4. Export. Open Import / Export (or use “Copy filter code” at the top), then paste the code into the game’s loot filter window.
      • 
    
    
  
    How rules work
    
    
    The order is the most important part of a filter.
    
    
      
     
    • Up to 40 rules. The game takes 40 rules at most. The counter at the top shows how many you use.
      • 
     
    • Top to bottom. The game checks the rules in list order. The first matching rule wins, and the rules below it are not looked at for that item.
      • 
     
    • No match. If no rule matches, the item is shown as normal.
      • 
     
    • Never hidden. Uniques, runes, Dwarven Runes, idols, the Cube, gems, currency, gold and flasks always stay visible, even when a hide rule matches. The Drop Test marks them SHOW*.
      • 
     
    • Rule on or off. The switch on a rule turns it off without deleting it. A rule that is off is skipped.
      • 
     
    • One line group per rule. To look for two line groups, use two rules.
      • 
    
    
  
    What a rule can check
    
    
    Everything you set on one rule must fit at the same time.
    
    
      
     
    • Rarity. Any, normal, magic, normal and magic, rare, rare and unique, and so on.
      • 
     
    • Item type. One type: any gear, weapons or a single weapon kind, armour slots, rings, amulets, belts, idols, gems, rune bases, core-touched, 4+ sockets or Truesworn.
      • 
     
    • Item level. One step: below 20, 40, 60 or 75, or 60, 75 or 82 and up. The MORE options also take a from–to range.
      • 
     
    • Line group. One group of affix lines, such as life, resistance, critical, minion or fire damage.
      • 
     
    • Roll quality. Any roll, good roll or top roll.
      • 
     
    • Lines needed. How many matching lines the item needs: 1+, 2+ or 3+.
      • 
    
    
  
    More conditions (the MORE button)
    
    
    All MORE options must fit together with the options above.
    
    
      
     
    • Tier. A tier and how many lines of that tier or better the item needs.
      • 
     
    • Sockets and levels. Sockets, item level and required level, as from–to ranges.
      • 
     
    • Grade. Base grade (50+, 70+, Truesworn) and top grade.
      • 
     
    • Reds. Reds only, or chase reds only. Unsworn or not.
      • 
     
    • Runes. Runes up to a chosen tier.
      • 
     
    • Named entries. Up to four named bases, lines or reds in one rule. A named line matches when the item has an affix of that line.
      • 
    
    
  
    Actions, colours and sounds
    
    
      
     
    • Hide. The item is not shown. Never works on the items listed under “Never hidden”.
      • 
     
    • Show. The item is shown as normal.
      • 
     
    • Highlight. The item name is drawn in the chosen colour.
      • 
     
    • Highlight + beam. Colour plus a light beam on the ground.
      • 
     
    • Colours. Ember, Jade, Frost, Bone, Gold, Blood, Ash and White.
      • 
     
    • Sounds. Auto (game default), Silent, Chime, Soft, Jewel and Wind.
      • 
    
    
  
    Building a good filter
    
    
      
     
    • Valuable first. Put the most precious rules (high rolls, top tiers, named reds) at the top, with Highlight + beam and their own colour and sound.
      • 
     
    • Then wider Highlights. Next come rules for items that are good but common, with a plain highlight or no sound.
      • 
     
    • Hide last. Rules that hide junk (low item level, normal or bad magic items) go near the bottom, so they cannot catch something above them.
      • 
     
    • Start from a preset. Load Tidy or Strict and change only what you need.
      • 
     
    • Check the order. A broad rule above a narrow one means the narrow one never fires. The rule list warns “May be caught by rule N” when it is sure. “Check rule order” in the Editor also runs sample items through your filter and lists rules that never decide anything.
      • 
     
    • Test before you trust. Always confirm the finished filter in the game.
      • 
    
    
  
    Using the Drop Test
    
    
      
     
    • Drop 1 / Drop 25 / Auto-drop. Random sample items. Reset clears the log and the counters.
      • 
     
    • Quick spawn. Targeted items: White, Magic good or bad, Rare valuable, decent, bad or mid, Unique / Red and Idol. Use these to test a rule that random drops rarely hit.
      • 
     
    • Sliders. “Lines at T1” sets how many T1 lines Rare valuable has (1–6), “Idol size” the idol size (1–4) and “Per click” how many items one press creates.
      • 
     
    • Result. The counters and the bar show how many drops are shown, highlighted or hidden. Hidden drops stay visible in the log with a dashed border.
      • 
     
    • Ground view and log. The ground view shows what you would see in the game. Each log entry names the rule that caught it, or says that no rule matched.
      • 
     
    • A best guess. Sample drops use real bases, affixes and uniques from the public API. How they are rolled has not been checked in the game.
      • 
    
    
  
    Import and export
    
    
      
     
    • The code. The game’s BOFILTER 1 code, for example BOFILTER:1,…. Copy it in the game’s loot filter window and paste it in Import / Export.
      • 
     
    • MORE options. They follow the ten numbers of a rule as ,3:key=value;key=value. The page reads them and you can change them in the Editor.
      • 
     
    • Unknown fields. Fields this page does not know are kept as they are.
      • 
     
    • Export. “Game code” is what you paste into the game. “Readable” is a plain list of your rules.
      • 
     
    • Saved in your browser. Your current filter is kept automatically, so it is still there next time.
      • 
    
    
  
    Keyboard shortcuts
    
    
      
     
    • Ctrl+Z undo the last change.
      • 
     
    • Ctrl+D duplicate the selected rule (Editor).
      • 
     
    • Alt+Up / Alt+Down select the previous or next rule (Editor).
      • 
     
    • Esc clear the rule search.
      • 
     
    • Left / Right arrow move between the tabs when a tab is focused.

    Real vs. guessed
    
    
    Real
    
    
    • BOFILTER 1 code format.
    • Rule order: the first match wins.
    • Limit of 40 rules (tested in the game).
    • The five game presets.
    • Bases, levels and tags; affix groups; unique names and bases (public API).
    
    
    From game files
    
    
    • MORE options and their keys (read from exported codes).
    • Lists of bases, named reds and named lines.
    • Item level of each affix tier.
    
    
    Guessed
    
    
    • Drop rates of bases and rarities; mods per item; which tier rolls.
    • Which affix belongs to which line group; what counts as a good or top roll.
    • Uniques: their mods are ignored by line rules.
    • How a Gems rule reads.
    • Random sample flags: core-touched, 4+ sockets, truesworn, rune base, grade, required level, unsworn, chase red, sample runes.
    • Left out: bases that never drop at random (core-touched, ashen, gnome-made) and uniques with drop weight 0.
    
    
    Not checked
    
    
    • Whether newer builds changed the code format. The developer file is older than the game (12 rules, the game takes 40).
    • If a game export does not load, please report it on GitHub.
